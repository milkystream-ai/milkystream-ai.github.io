# 마구로그 (Magu-Log)

## 한 줄 요약
운동·독서 같은 생산적인 활동을 기록하면 점수가 쌓이고, 점수에 따라 **선수카드 쿠폰 코드**가 나온다. 이 코드를 마구로드에 입력하면 선수카드를 받는다.

## 완성 기준
1. 폰과 PC 브라우저에서 활동(종류·분·메모)을 기록하고, 다시 열어도 기록이 남아 있다.
2. 규칙(SPEC.md 5장)대로 티켓이 생기고, 티켓마다 쿠폰 코드가 나온다.
3. 그 코드를 마구로드에 넣으면 해당 등급 카드가 지급되고, 같은 코드를 다시 넣으면 거절된다.

## 기술 스택
- **HTML + CSS + 순수 JavaScript 파일 1개(`index.html`)**: 빌드 도구 없이 PC와 폰 브라우저에서 바로 돌아간다. 사용자가 비개발자라 고치기도 쉽다.
- **호스팅: GitHub Pages** (`https://milkystream-ai.github.io/magu-log/`): 이 저장소가 이미 Pages 사이트라서 추가 비용·설정이 없다.
- **저장: 브라우저 `localStorage`**: 사용자가 1명뿐이라 서버와 DB가 필요 없다.
- **서명: Web Crypto API (`crypto.subtle`, HMAC-SHA256)**: 브라우저 내장 기능이라 라이브러리를 추가하지 않아도 된다.
- **마구로드와의 연결: 쿠폰 코드 방식.** 마구로드 코드는 사용자 PC에만 있고 저장 방식도 확실하지 않다. 그래서 두 프로그램이 같은 저장소를 공유하지 않아도 되는 방식을 고른다. 공유 비밀키로 서명한 문자열 하나만 주고받는다.

## 파일 구조
```
magu-log/
├── CLAUDE.md
├── SPEC.md
├── index.html      # 화면 + 로직 전부 (1단계~5단계)
└── manifest.json   # 홈 화면 추가용 (6단계, 선택)
```
`index.html`이 1,500줄을 넘기 전에는 파일을 나누지 않는다.

## index.html 안의 구역 (주석으로 구분)
| 구역 | 하는 일 | 하지 않는 일 |
|---|---|---|
| `// === STORE ===` | localStorage 읽기/쓰기, JSON 내보내기·가져오기 | 점수 계산 |
| `// === RULES ===` | 기록 → 점수, 점수 → 받을 티켓 목록 계산 (순수 함수) | 화면, 저장 |
| `// === COUPON ===` | 티켓 → 쿠폰 코드 생성 (HMAC) | 티켓 발급 판단 |
| `// === UI ===` | 화면 그리기, 버튼 이벤트 처리 | 계산 로직 직접 작성 |

## 핵심 데이터 구조
```js
// localStorage key: "maguLog.v1"
{ settings: { secret, dailyGoal: 30, categories: [...] },
  records: [{ id, date: "2026-10-08", category: "운동", minutes: 40, memo }],
  tickets: [{ id: "7KQ2M", grade: "N", ruleKey: "N|3", issuedAt, code, used: false }] }
```

## 쿠폰 코드 형식 (마구로드와 공유하는 약속 — 바꾸지 말 것)
```
MR1-{등급}-{티켓ID 5자}-{서명 8자}      예) MR1-N-7KQ2M-PERWMHY3
서명 = HMAC-SHA256(secret, "MR1|{티켓ID}|{등급}") 앞 40비트 → Crockford Base32 8자
```
세부 규칙과 테스트 값은 SPEC.md 6장에 있다. **구현이 끝나면 테스트 값과 결과가 같은지 반드시 확인한다.**

## 코딩 규칙
- 화면 문구는 모두 한국어로, 짧고 친근하게 쓴다. 예: "오늘 40분 운동! +40점"
- 날짜는 기기의 현지 시간으로 `YYYY-MM-DD` 문자열을 쓴다. UTC로 바꾸지 않는다. 한국 시간 자정 전후에 날짜가 밀리면 안 되기 때문이다.
- 저장 실패나 JSON 파싱 실패가 나면 화면 위쪽에 빨간 안내줄을 띄운다. 오류를 조용히 넘기지 않는다.
- 손상된 저장 데이터를 발견하면 덮어쓰기 전에 `maguLog.v1.broken.{시각}` 키로 백업한다.
- 외부 라이브러리와 CDN을 추가하기 전에는 사용자에게 먼저 묻는다.

## 하지 말 것
- **비밀키(secret)를 코드에 적지 말 것.** 이 저장소는 공개(public)라서 누구나 코드를 볼 수 있다. 비밀키는 사용자가 설정 화면에서 직접 입력한다.
- 이미 발급한 티켓은 회수하거나 삭제하지 말 것. 기록을 지워도 티켓은 남는다. 대신 그 뒤로 새 티켓이 나오는 것만 늦어진다.
- 서버, DB, 로그인, 프레임워크(React 등), 빌드 도구(npm, Vite 등)를 넣지 말 것. 사용자는 1명이고 파일 1개면 충분하다.
- 쿠폰 형식(`MR1-...`)을 바꾸지 말 것. 바꾸면 마구로드 쪽도 함께 고쳐야 한다. 꼭 바꿔야 하면 `MR2`로 새 버전을 만들고 먼저 사용자에게 묻는다.
- 카드의 이름·능력치·이미지는 이 앱에서 정하지 말 것. 이 앱은 **등급(N/R/E/L)만** 정하고, 어떤 카드를 줄지는 마구로드가 정한다.
- 저장소 루트의 `index.html`, `privacy.html`은 건드리지 말 것. 다른 앱들의 안내 페이지다.
- 명세에 없는 기능을 마음대로 추가하지 말 것. 이 문서와 다른 구조로 바꾸려면 먼저 물어볼 것.

## 구현 순서
1. **기록하기**: 활동 종류(드롭다운)·분·메모를 입력하고 [기록] 버튼을 누르면 오늘 목록에 보인다. 새로고침해도 남아 있다.
2. **점수와 티켓**: 오늘 점수, 누적 점수, 연속 달성 일수를 보여 준다. 규칙에 따라 티켓이 생기면 "🎟️ 새 티켓!" 알림을 띄운다.
3. **쿠폰 코드**: 설정에서 비밀키를 입력하면 티켓마다 코드가 나오고 [복사] 버튼이 생긴다. SPEC 6장의 테스트 값과 결과가 일치해야 한다.
4. **마구로드에 쿠폰 입력 기능 추가**: 이 단계는 마구로드 프로젝트에서 작업한다. 사용자 PC에 있는 마구로드 폴더로 SPEC.md 7장을 가져가서 구현한다.
5. **백업**: JSON 내보내기·가져오기. PC↔폰 사이 이동과 기기 교체에 대비한다.
6. (선택) `manifest.json`을 추가해 폰 홈 화면에 아이콘으로 띄운다.

1단계만 끝내도 "기록 앱"으로 쓸 수 있어야 한다. 상세 명세는 SPEC.md 참조.
