# 마구로그 상세 명세

## 1. 배경과 목적
- 사용자는 클로드코드로 직접 만든 야구 카드 게임 **마구로드**를 PC와 폰(APK)에서 하고 있다.
- 운동·독서 같은 좋은 습관을 이어가는 동기를 만들고 싶다. 그래서 "현실에서 노력하면 → 게임에서 선수카드를 받는" 구조를 만든다.
- 마구로드 코드는 사용자 PC에만 있다(GitHub에 없음). 카드 데이터 저장 방식도 확실하지 않다("구글드라이브 같음"). 그래서 두 프로그램 사이는 **쿠폰 코드 한 줄**로만 연결한다. 이렇게 하면 마구로드의 내부 구조와 상관없이 연동된다.

## 2. 사용자와 사용 시나리오
- 사용자: 본인 1명. PC와 안드로이드폰을 둘 다 쓴다.
- 시나리오 A (매일): 운동을 마치고 폰으로 마구로그를 연다 → "운동 40분" 기록 → +40점 → 누적 점수가 100점을 넘으면 "🎟️ 일반 티켓!" 알림.
- 시나리오 B (카드 받기): 마구로그의 티켓 목록에서 [복사]를 누른다 → 마구로드를 연다 → 쿠폰 입력 칸에 붙여넣는다 → 카드 뽑기 연출 후 카드가 지급된다 → 마구로그로 돌아와 [사용함]에 체크한다(선택).

## 3. 기능 목록
| # | 기능 | 우선순위 | 완료 조건 |
|---|---|---|---|
| F1 | 활동 기록 | 필수 | 종류·날짜(기본값: 오늘)·분·메모(선택)를 저장하고, 새로고침 후에도 남는다 |
| F2 | 기록 수정/삭제 | 필수 | 목록에서 수정·삭제할 수 있다. 삭제할 때 확인창을 띄운다 |
| F3 | 점수 대시보드 | 필수 | 오늘 점수 / 하루 목표 진행 막대 / 연속 달성 일수 / 누적 점수 / 다음 일반 티켓까지 남은 점수 |
| F4 | 티켓 자동 발급 | 필수 | 5장의 규칙대로 발급되고, 같은 규칙으로는 두 번 발급되지 않는다 |
| F5 | 쿠폰 코드 | 필수 | 6장 형식에 맞고, 테스트 값과 일치한다. [복사] 버튼이 있다 |
| F6 | 설정 | 필수 | 비밀키, 하루 목표 점수, 활동 종류 추가·삭제 |
| F7 | 백업 | 필수 | JSON 파일 내보내기·가져오기. 가져오기는 합치기 방식(9장 참고) |
| F8 | 마구로드 쿠폰 입력 | 필수 | 7장. 마구로드 프로젝트 쪽에서 작업 |
| F9 | 홈 화면 아이콘 | 선택 | manifest.json, 아이콘 1개 |

## 4. 화면 (한 페이지, 위에서 아래 순서)
1. **헤더**: "⚾ 마구로그" + 톱니바퀴(설정)
2. **오늘 카드**: 오늘 점수 / 목표, 진행 막대, "🔥 N일 연속"
3. **기록 입력**: 종류 드롭다운, 분(숫자, 1~600), 메모, [기록] 버튼
4. **최근 기록**: 최근 14일 기록. 날짜별로 묶어서 보여 준다
5. **티켓함**: 사용하지 않은 티켓을 위에 둔다. 등급 배지 색은 N 회색 · R 파랑 · E 보라 · L 금색. 코드, [복사], [사용함] 체크박스
6. **설정 (접힘)**: 비밀키, 하루 목표, 활동 종류, 내보내기/가져오기

폰 세로 화면(360px)에서 가로 스크롤 없이 보여야 한다. 다크모드도 지원한다(`prefers-color-scheme`).

## 5. 점수와 티켓 규칙
### 점수
- **1분 = 1점.** 모든 활동 종류가 같다.
- 기본 활동 종류: 운동, 독서, 공부, 글쓰기, 얼굴 재활운동, 기타. 설정에서 추가·삭제할 수 있다.
- 하루 목표: 기본 30점. 그날 점수 합이 목표 이상이면 그날은 "달성일"이다.

### 티켓 (등급 4개)
| 등급 | 코드 | 조건 | ruleKey (중복 방지용) |
|---|---|---|---|
| 일반 | N | 누적 점수 100점마다 1장 | `N\|{순번}` 예: `N\|1`, `N\|2` |
| 레어 | R | 달성일이 연속 7일 될 때마다 1장 (7, 14, 21…일째) | `R\|{연속 시작일}\|{7의 배수}` |
| 에픽 | E | 달성일이 연속 30일 될 때마다 1장 (30, 60…일째) | `E\|{연속 시작일}\|{30의 배수}` |
| 레전드 | L | 한 달(1일~말일) 점수 합 1,500점 이상이면 그 달 1장 | `L\|{YYYY-MM}` |

### 발급 알고리즘
1. 기록이 바뀔 때마다(추가·수정·삭제·가져오기) `RULES.computeEarnedKeys(records, settings)`로 지금 받을 자격이 있는 ruleKey 전체 목록을 다시 계산한다.
2. 그 목록에서 `tickets`에 이미 있는 ruleKey는 빼고, 남은 것만 새 티켓으로 만든다.
3. **티켓은 지우지 않는다.** 기록을 지워서 자격이 사라져도 이미 받은 티켓은 그대로 둔다.
4. N 순번은 `floor(누적점수 / 100)`까지 1부터 센다. 기록을 지웠다가 다시 쓰면 이미 받은 순번은 건너뛴다.
5. 연속 일수는 날짜 문자열을 기준으로 센다. 기록이 없는 날이나 목표에 못 미친 날에서 연속이 끊긴다.

### 티켓 ID
- Crockford Base32 문자(`0123456789ABCDEFGHJKMNPQRSTVWXYZ`) 5자를 `crypto.getRandomValues`로 만든다.
- 순번이 아니라 랜덤으로 만드는 이유: PC와 폰에서 따로 발급해도 ID가 겹치지 않게 하려는 것이다.
- 이미 있는 ID와 겹치면 다시 만든다.

## 6. 쿠폰 코드 (마구로그 ↔ 마구로드 공통 약속)
```
형식:   MR1-{G}-{ID}-{SIG}
G:      N | R | E | L
ID:     티켓 ID 5자 (Crockford Base32)
SIG:    HMAC-SHA256(key = UTF-8(secret), msg = UTF-8("MR1|" + ID + "|" + G))
        → 결과 바이트의 앞 40비트를 5비트씩 끊어 Crockford Base32 8자로 바꾼다 (대문자)
```
- 마구로드에서 입력을 받을 때: 앞뒤 공백을 지우고 대문자로 바꾼다. `O`는 `0`으로, `I`·`L`은 `1`로 바꾼다. 단, 등급 자리의 `L`은 바꾸지 않는다. 그래서 하이픈으로 먼저 나눈 뒤 ID·SIG 부분에만 적용한다.
- **비밀키**: 사용자가 정한 문구(8자 이상). 마구로그와 마구로드 양쪽 설정에 같은 값을 넣는다. 코드나 저장소에는 넣지 않는다.

### 테스트 값 (양쪽 구현 모두 반드시 통과)
| secret | ID | G | 기대 코드 |
|---|---|---|---|
| `test-secret-1234` | `7KQ2M` | N | `MR1-N-7KQ2M-PERWMHY3` |
| `test-secret-1234` | `A3ZP9` | R | `MR1-R-A3ZP9-WQCRSF2K` |

## 7. 마구로드 쪽 작업 명세 (마구로드 프로젝트에서 구현)
> 이 장은 사용자 PC의 마구로드 폴더에서 작업하는 모델을 위한 것이다. 마구로드 코드를 먼저 읽고, 마구로드의 기존 구조와 말투를 따른다.

1. **설정**: "마구로그 비밀키" 입력란을 추가하고 마구로드 저장소에 보관한다.
2. **쿠폰 입력 화면**: 메뉴에 "🎟️ 쿠폰 입력"을 추가한다. 입력칸과 [받기] 버튼을 둔다.
3. **검증 순서**: 형식 검사 → 서명 재계산·비교 → 사용한 쿠폰 목록에 있는 ID인지 확인 → 통과하면 카드 지급.
4. **사용한 쿠폰 목록**: 사용한 티켓 ID를 마구로드의 저장 데이터(카드 데이터와 같은 곳)에 영구 보관한다. 그래야 PC와 폰에서 중복으로 받지 못한다.
5. **등급 매핑**: N/R/E/L을 마구로드의 기존 카드 등급과 짝짓는다. 매핑표는 마구로드 코드를 읽은 뒤 사용자에게 확인받는다. (마구로그는 등급만 정한다.)
6. **지급**: 해당 등급의 카드 풀에서 무작위로 1장을 준다. 기존 카드 뽑기 연출이 있으면 그대로 다시 쓴다.
7. **오류 문구**: "코드 형식이 달라요" / "비밀키가 다르거나 잘못된 코드예요" / "이미 받은 쿠폰이에요"
8. 6장의 테스트 값으로 서명이 일치하는지 확인한다.

## 8. 예외 상황과 처리 방침
| 상황 | 처리 |
|---|---|
| 분이 비었거나 0 이하이거나 600 초과 | [기록] 버튼을 막고 입력칸 아래에 안내 문구를 띄운다 |
| 비밀키가 설정되지 않음 | 티켓은 발급하되, 코드 자리에 "설정에서 비밀키를 넣어 주세요"를 표시한다 |
| 비밀키를 바꿈 | 이미 만든 코드는 그대로 둔다. "바꾼 뒤 새로 생기는 티켓부터 새 키가 쓰여요. 마구로드 쪽 키도 같이 바꿔 주세요"라고 경고한다 |
| localStorage가 손상됨 | `maguLog.v1.broken.{시각}`으로 백업하고, 빈 데이터로 시작하면서 빨간 안내줄을 띄운다 |
| `crypto.subtle`을 쓸 수 없음 (http, 오래된 브라우저) | "https 주소로 열어 주세요"라고 안내한다. GitHub Pages는 https라서 보통은 생기지 않는다 |
| 가져오기 파일 형식이 틀림 | 아무것도 바꾸지 않고 "백업 파일이 아니에요"라고 안내한다 |

## 9. 백업 가져오기 (합치기 규칙)
- records: `id`가 같으면 건너뛰고, 없으면 추가한다.
- tickets: `id`가 같으면 건너뛴다. `used`가 하나라도 true면 true로 둔다.
- settings: 바꾸지 않는다. 비밀키는 백업 파일에 넣지 않는다. 백업 파일이 유출될 경우를 대비한 것이다.
- 합친 뒤에 티켓 발급 계산을 다시 한다. 같은 ruleKey가 이미 있으면 새로 발급하지 않는다.

## 10. 제약 조건
- 인터넷만 되면 PC와 폰 브라우저 어디서든 쓸 수 있어야 한다 (Chrome 최신 버전 기준).
- 데이터 규모: 하루 5건 × 10년 ≈ 18,000건. localStorage 5MB 안에 들어간다. 목록은 최근 14일만 그린다.
- 페이지는 공개 주소지만 데이터는 각 기기 브라우저에만 저장된다. 다른 사람이 주소를 열어도 빈 앱이 보일 뿐이다.
- 보안 수준: 개인 게임용이다. 비밀키를 아는 본인은 쿠폰을 위조할 수 있지만 문제 삼지 않는다. 목적은 실수나 장난을 막는 것이다.

## 11. 이번에 만들지 않는 것
- **PC↔폰 자동 동기화 (구글 드라이브 연동)**: 마구로드의 실제 저장 방식을 확인한 뒤 2차로 검토한다. 그때까지는 9장의 백업 파일로 옮긴다. 쿠폰 방식은 동기화 없이도 동작한다.
- 마구로드로 카드를 자동 전달하는 기능 (코드를 직접 붙여넣어야 함)
- 알림·푸시, 통계 그래프, 활동별 점수 가중치, 사진 첨부
- 로그인과 여러 사용자 지원
